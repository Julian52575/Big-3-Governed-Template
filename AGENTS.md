# Agent instructions

First find out which repository you are in: `git remote get-url origin`
(GitHub redirects renamed repositories, so `gh repo view --json nameWithOwner`
gives the current name).

## Working on Julian52575/Big-3-Governed-Template (the template repo)

This repository does not deliver a project. It delivers the governance and
DevOps tooling to build one: the Nix dev shell, the `justfile`, the compose
stack, CI and release workflows, the repository rules and `adapt.py`. The
`frontend/` and `backend/` services are placeholders that exercise that
tooling; keep them minimal. Every change should make sense for any project
created from the template.

Read [README.md](README.md), [CONTRIBUTING.md](CONTRIBUTING.md) and
[README-ADAPT.md](README-ADAPT.md) before changing anything; they are the
source of truth. The hard rules:

- **Conventional Commits** for every commit and PR title:
  `<type>[(scope)][!]: description`, lower-case subject, no trailing period.
- **Signed, signed-off commits**: `git commit -s` with signing configured;
  the `commit-msg` hook rejects anything else.
- **Link the issue** a PR resolves (`Closes #NNN` in the body). Branch from `main`;
  never push to `main`.
- **Workflows** (`.github/`):
  - pin every action to a full commit SHA with a `# vX.Y.Z` comment that
    matches it (`pin-github-action` does this);
  - least-privilege `permissions:` at workflow level, widened per job only
    where needed;
  - `timeout-minutes` on every job, `step-security/harden-runner` as each
    job's first step, `persist-credentials: false` on every checkout;
  - never expand `${{ … }}` inside `run:` — pass it through `env:`;
  - make a new job mandatory by adding it to `ci-required.needs` in
    `ci.yml`, never by editing `.github/rulesets/main.json`.
  - Run `just lint-workflows` (actionlint, zizmor, schema) before committing.
- **Tooling** comes from the Nix dev shell (`nix develop`). Add a tool to
  `flake.nix`, or to `nix/tools.nix` when nixpkgs lags the version CI uses.
- **No OS-specific scripts**: new helper scripts are Python 3 (standard
  library only, like `adapt.py`), not shell, so they run on Linux, macOS and
  Windows. `justfile` recipes stay one-liners that call them.
- **Secrets** never go in git. New variables go in `.env.example` with a safe
  placeholder; `change-me-*` values are generated by the shell.
- **Template placeholders** (`OWNER/REPO`, `[INSERT CONTACT METHOD]`,
  `REPLACE_WITH_*`, …) stay as they are; a new one must be handled by
  `adapt.py` and listed in README-ADAPT.md.
- **Comments** stay short and explain why, not what.
- Record incidents and their fixes under `docs/troubleshooting/<area>/`
  (see CONTRIBUTING.md).
- AI-assisted commits carry a `Co-Authored-By:` trailer naming the assistant.

## Working on a repository created from the template

Follow [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md); they
describe this project's stack and rules.

**Tell the user, once per session,** that this AGENTS.md is still the
template's: the section above describes the template repository, not their
project. Suggest they rewrite it for their project, keeping only the rules
that still apply.

**If the repository is not adapted yet** (`./adapt.py --workflow` reports
failures, or template placeholders such as `OWNER/REPO` remain), recommend
letting you guide them through [README-ADAPT.md](README-ADAPT.md). Then follow
it step by step: explain each step, run `adapt.py` with them, and show every
command before running it. Never ask for secret values in the chat; let the
user type them into `adapt.py --gh-vars` themselves.
